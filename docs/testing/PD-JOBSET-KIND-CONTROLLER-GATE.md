# Disposable PD JobSet controller acceptance gate (no GPU proof)

This PR wires two existing tests from Draft #115 into the current main `Kueue real-controller kind smoke` workflow. Only `.github/workflows/kueue-kind-smoke.yml`, `scripts/kueue_kind_smoke.sh`, two new `scripts/pd_jobset_*.sh` tests and this documentation change. **No production runtime handler, Kubernetes JobSet staging writer, policy issuer or real GPU is added.**

The first smoke installs **JobSet v0.13.0** into the explicit disposable Kubernetes 1.34 / Kueue v0.19.6 / simulated DRA cluster (JobSet v0.13.0 manifest SHA256 is pinned to the exact observed test artifact `41b599b721eca22af5bcb7a1802b976c389933759aab510daeeb40afcc775a90`; this checks content drift but is not independent vendor signing/attestation). It creates an isolated namespace and 1-device quota, then confirms the same single paired JobSet produces **one** Kueue Workload with two phase PodSets, denies at one GPU device quota with no Pods/Claims, and admits both phase assignments when quota rises to two. This proves scheduler/controller behavior only.

The second smoke creates a distinct suspended JobSet with the `kueue.x-k8s.io/admission-gated-by` label and tests that even with spare quota it remains non-admitted, suspended, with no Pods; separately creates **scoped** staging GET/CREATE and activator GET/PATCH-only ServiceAccounts, verifies privileged operations are denied via `kubectl auth can-i`, and checks that the unauthorized staging actor cannot remove the gate while the narrowly scoped test activator can. Its JSON PATCH includes UID and original annotation preconditions. The activator's impersonation is a **test fixture**, not a production permit verifier.

All changes run only when `CCP_DISPOSABLE_KIND_SMOKE=1` and exact source checkout/hash is verified. Existing main Kueue/DRA tests are retained. Kind uses fake device inventory and does not establish a real GPU, actual driver `NodePrepareResources`/`NodeUnprepareResources`, physical release, provider absence, G04/G05 or Cost FINAL. This does not run the other two #115 provider/PG end-to-end scripts; those require future independently scoped staging and durable binding integration.
