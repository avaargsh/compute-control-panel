# Unmounted PD JobSet staging adapter — development-only acceptance

**Source:** historical Draft #115 `44a0a61fe6a1b98e96d389c6d66f179bb9643a0c`. **Base:** `main@63df9c3333bd1b56d1a8cbce4b5b1b04236700fe`. Five new `internal/provider/pd_jobset_*` Go source and test files are extracted with no ServiceAccount YAML, API route, running worker, side-effect fence, database migration, activation webhook or script hooks.

`PDJobSetAdapter.Apply` is **capable of a Kubernetes POST to create a JobSet if an authorized caller invokes it with Kubernetes access**. This is NOT a read-only module. Therefore this code MUST NOT be treated as safe to deploy or route from a generic Provider adapter or public API. Only a future independent staging path that holds the current source/Generation/Operation lease fence at the exact side-effect boundary may call it. The Go package's constructor and the `PDJobSetPlan` fields cannot authenticate the plan's provenance or independently prove Kubernetes RBAC, admission-controller activation gate enforcement, or ResourceClaimTemplate GPU cardinality.

The adapter accepts only a pinned canonical PD Operation ID, request digest, provider/workload/tenant/generation and single GPU per replica. Its expected object is suspended and carries an `admission-gated-by` annotation, but the annotation's existence **does not prove** Kueue's controller enforces it. It uses one strictly named JobSet and durable Kubernetes UID binding, returns UNKNOWN/ACK-lost if a prior POST may have succeeded but no authentic UID can be correlated, and rejects drift in signed intention, UID, Pod spec, image, annotations or server-defaulted JobSet spec. It NEVER unsuspends/activates/deletes or claims a physical GPU.

The production in-cluster constructor requires a pre-existing independently privileged-checked PostgreSQL binding store and projected rotating ServiceAccount credentials, **but does not itself prove** the ServiceAccount is scoped CREATE/GET only. The testing constructor accepts arbitrary bindings and MUST NOT be used for an actual worker.

**Exact-head acceptance before merging an unmounted library:** full Go vet/test/race/SIGKILL, real PostgreSQL release-fence checks, evidence declaration. This package-only diff does not run the 4 dedicated PD kind scripts. Before any actual staging deployment require real JobSet/Kueue/controller/AdmissionGatedBy validation with strict GET/CREATE RBAC, disabled unsuspend/UPDATE/PATCH/DELETE, ephemeral rollback/reconciliation, signed current source and lease in the same transaction around the POST, and inspect-first UNKNOWN on SIGKILL or lost ACK. Physical driver Prepare/Unprepare, occupancy, release G04/G05 and finance FINAL are separate hard gates.
