# PD atomic promotion — isolated development merge scope

Source Draft #115 `7ea4e9de1e2ba74c9df5653a01fbd6fc3a5d87a4`; based on `main@4c2722e11400b43f3ace63d017bda575b1891f8a` **after** the non-actuating PD Intent journal and generic `pd-operation-` dispatch block were merged.

This package adds `PromotePDIntent` and migration 0021. Under PostgreSQL row locks and generation CAS, it checks the independently recorded immutable PD intent, current trusted source/fence version/expiry, registered Provider, matching ownership and Workload desired generation, and the previous canonical Allocation's `RELEASED` phase. One transaction advances the Workload Generation, creates a **PENDING** next-generation Allocation and reserved **PENDING** `pd-operation-<intent-id>` CREATE Operation, emits distinct `compute.pd.operation.staged.v1` non-generic dispatch Outbox, and commits immutable promotion evidence. SQL deferrable commit-time guards independently recheck source authority, Provider and canonical identity after lock waits. An old/uncertain Allocation blocks promotion. Replay must not duplicate operations or bypass current canonical provenance.

**Important trust boundary:** this operation changes **database intent state**, so only a trusted, independently authenticated control-plane component may call it; it is not a public API route, user mutation endpoint, scheduler or physical device manager. This split does not register a caller or grant runtime role permissions. The separately merged #158 generic `ClaimOperation`/`StartOperation` guard prohibits dispatching reserved PD operations without future `ClaimPDStagingOperation` source checks. No Kubernetes JobSet POST, admission activation, DRA driver Prepare/Unprepare, physical device release, usage or finance FINAL is implemented by this module.

`Allocation RELEASED` is a **prerequisite observed in the canonical DB**, not a physical release proof generated by this code. The existing independent allocation release reconciliation must already establish its evidence; simulated test rows are not hardware acceptance. No automated external side effect or G04/G05 closure is claimed.

**Test gate:** exact HEAD merged-tree Go full tests, race/SIGKILL, real PostgreSQL migration/schema and commit-time fence/race/revocation/expiry/old Allocation failure/replay tests, source-pinned independent release-fence checks and Evidence declaration. This source-only migration split does not trigger Kubernetes/kind or a physical GPU test; those remain future integration gates for #115.
