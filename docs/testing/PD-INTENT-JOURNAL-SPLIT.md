The independently authorized and verified `pd.VerifiedProposal` is pinned to a specific Tenant/Project/owner, Provider, Workload, target Generation, matching digest, authoritative fence revision, current clock and expiry. `RecordPDIntent` uses PostgreSQL Workload/fence/Provider locks, immutable intent journal and a non-dispatchable `compute.pd.intent.recorded.v1` Outbox event in one transaction. The database trigger and deferred commit guard reject authority revocation/expiry/generation drift. Replay returns the original recorded event without creating a new dispatch.

**No automatic execution:** Recording a proposal does not advance the Workload desired generation, create an Allocation or Operation, schedule a JobSet, authorize any Kubernetes POST/PATCH, or confer a lease. The accepted proposal is not physical GPU evidence, driver `NodePrepareResources`, release, Cost FINAL, G04 or G05. `GetRecordedPDIntent` is a historical record check, not fresh source authority. Provisioning the independent fence and the authenticated verified proposal remains an explicit trusted source responsibility; no external HTTP endpoint or dispatcher is added.

**Acceptance:** exact-head Go full race/static/SIGKILL, checksum migration/idempotency, real PostgreSQL positive/negative replay/CAS/revocation and source-pinned release-fence jobs, plus Evidence declaration. The package-only migration diff does not activate live Kubernetes and does not claim a kind/GPU run. Production grants, forensic provenance and physical hardware are separate gates.
