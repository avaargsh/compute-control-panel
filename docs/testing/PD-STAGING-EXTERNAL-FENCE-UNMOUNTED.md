# Unmounted DB staging side-effect fence — development-only split

Original Draft #115 source `44a0a61fe6a1b98e96d389c6d66f179bb9643a0c`; based on `main@63df9c3333bd1b56d1a8cbce4b5b1b04236700fe` after #159–#161 durable Intent/Promotion/DB lease and #158 reserved PD ID generic dispatch block.

`WithCurrentPDStagingFence` is a low-level PostgreSQL Repository callback wrapper. **The method can execute an external side effect through its caller-supplied `stageCreate` callback**. No production caller is mounted in this PR, no callback is registered to an API, no ServiceAccount, Kubernetes client/JobSet writer or user workflow is introduced. The caller MUST be a separately trusted staging-only execution boundary; the wrapper does not prove callback restrictions, Kubernetes RBAC or signed hardware identity.

Before invoking a callback it locks current Workload/Generation/independent PD source/fence/version/Provider, canonical promoted Allocation, and exactly leased IN_FLIGHT reserved PD Operation in the same real PostgreSQL transaction. It rejects revocation, expired source or lease, wrong worker/version/fence, and any stale state. The callback receives a DB-clock-bounded context while the DB row locks are held; callbacks must honor cancellation and must not reenter the same Repository or block beyond that budget. On error or expiry after a possibly accepted CREATE, it advances the Operation to durable UNKNOWN if possible and returns `ErrPDStagingWriteUncertain`; a database commit failure after an external effect is also uncertain and MUST be resolved by inspect-first, never a blind retry. Successful callback return **does not advance** Operation to SUCCEEDED or Allocation to READY.

Tests run on real PostgreSQL: current lease positive path, wrong worker/token/version rejection before callback, revoked/stale/drained/expired conditions, UNKNOWN persistence after lost ACK and no replay across Repository restart, and lock contention proving an external revoker cannot pass while the callback executes. This is **not a physical GPU/device release test** or JobSet controller acceptance.

**Exact-head gate**: full Go/race/SIGKILL and PG schema/migration/source pinned release-fence tests, Evidence declaration. **No Kubernetes/kind is run** for this package-only extraction. Before any actual side effect runs in production, require independently provisioned restricted GET/CREATE ServiceAccount, real JobSet/Kueue/AdmissionGatedBy controller acceptance, trusted source and authentic external device/driver receipts.
